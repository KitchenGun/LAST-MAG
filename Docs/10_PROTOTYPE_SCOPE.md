# 프로토타입 범위

## 문서 목적

이 문서는 최초 제출 버전이 반드시 제공해야 하는 플레이 경험과 제작 중 추가하지 않을 범위를 고정한다. 기능의 존재뿐 아니라 시작부터 재시작까지 한 판이 완결되는지를 기준으로 삼는다.

## 완성 단계

| 단계 | 의미 | 완료 기준 |
| --- | --- | --- |
| 코어 플레이 | 게임의 반복 행동을 검증하는 상태 | 이동, 사격, 적 처치, 탄약 회수, 피격, 사망, 재시작이 연결됨 |
| 제출 가능 버전 | 외부 플레이어가 브라우저에서 한 판을 이해하고 끝낼 수 있는 상태 | 클래스 3종의 고정 로드아웃·고유 스킬, 적 3종, 점수·콤보, HUD, 결과 화면, 기본 사운드가 포함됨 |
| 최종 제출 버전 | 기록 경쟁과 외부 배포까지 포함한 상태 | 온라인 랭킹, WebGL 안정화, 외부 환경 검증, 제출 자료가 완료됨 |

## 필수 콘텐츠

| 영역 | 필수 범위 | 완성 판정 |
| --- | --- | --- |
| 플레이어 | 클래스 선택, 1인칭 이동, 시점, 점프, 사격, 무기 전환, 스킬 | 조작이 즉시 반응하고 전투 중 입력 상태를 이해할 수 있음 |
| 생존 | 체력, 피해, 자동 회복, 사망 | 피격과 회복 시작·중단·사망 원인이 명확함 |
| 클래스 | 척탄병·공병·저격수 | 같은 체력·이동 속도에서 고정 로드아웃과 스킬 역할이 다름 |
| 무기 | 권총, 샷건, 라이플, DMR | 역할과 탄약 사용, 점수 보상이 서로 다름 |
| 탄약 | 적 처치 드롭, 권총·샷건·라이플 계열 탄약, 자동 획득 | 표시 범주는 3종이며 런타임 보유 슬롯은 DMR을 포함한 4종이다. DMR은 라이플과 파란색·드롭 규칙을 공유하지만 별도 탄약을 사용한다 |
| 적 | 자폭형 적, 일반 근거리 적, 원거리 공격 적 | 공격 예고와 대응 방법이 서로 다름 |
| 난이도 | 시간에 따른 연속 상승 | 적 능력치 변화 없이 수량·빈도·조합으로 압박이 커짐 |
| 맵 | 군사 산업 SF 아레나 1개 | 중앙과 외곽을 순환하며 근·원거리 전투가 모두 발생함 |
| 점수 | 헤드샷·스왑킬·스킬 가산점, 무상한 5초 콤보, 생존 시간 | 공격적인 플레이가 단순 생존보다 높은 점수로 이어짐 |
| UI | 시작, 조작 안내, HUD, 결과, 재시작 | 처음 플레이한 사람이 별도 설명 없이 한 판을 진행함 |
| 기록 | 브라우저 개인 최고점 | 새로고침과 브라우저 재실행 뒤에도 같은 환경에서 유지됨 |
| 랭킹 | 닉네임 제출, 상위 10개, 현재 점수 백분위 | 성공·실패 상태가 결과 화면에서 구분됨 |
| 오디오·피드백 | 기본 BGM, 무기·적·UI 효과음, 시각 피드백 | 주요 전투 사건을 화면과 소리로 동시에 인지함 |
| 배포 | Unity WebGL | 외부 브라우저에서 시작, 사망, 결과, 재시작이 가능함 |

## 빌드 버전 규칙

- `MAJOR.MINOR.PATCH`는 Unity 프로젝트의 제품 버전을 사용한다.
- `MAJOR`는 호환되지 않는 큰 구조 변경, `MINOR`는 플레이 가능한 기능 추가, `PATCH`는 밸런스·버그 수정 배포에서 올린다.
- 빌드 요청 시 마지막 배포 이후 변경이 있으면 별도 확인 없이 `PATCH`를 1 올린 뒤 빌드한다. 사용자가 기능 마일스톤이나 호환성 변경을 지정한 경우에만 `MINOR` 또는 `MAJOR`를 올린다.
- 변경이 없는 단순 재빌드는 제품 버전을 유지하고 빌드마다 새로 생성되는 `BUILDID`만 변경한다.
- WebGL 시작 화면에는 `vMAJOR.MINOR.PATCH · WEB-BUILDID`로 표시한다.
- `BUILDID`는 Unity가 빌드마다 생성하는 GUID의 앞 8자리다. 같은 제품 버전으로 여러 테스트 빌드를 배포해도 테스터가 정확한 빌드를 구분할 수 있다.
- 에디터 실행은 자동 빌드 ID 대신 `WEB-EDITOR`로 표시한다.

## WebGL 초기 로딩 원칙

- 첫 방문 또는 새 제품 버전은 `.data`, `.wasm`, framework, loader를 다운로드하고 WebAssembly와 Unity 데이터를 초기화하므로 재방문보다 오래 걸릴 수 있다.
- `webGLDataCaching`은 같은 제품 버전의 재방문 캐시를 돕지만, 새 버전의 파일명과 캐시 항목은 다시 받아야 한다. 캐시가 저장되지 않는 브라우저에서는 매번 냉 캐시와 같은 조건이 된다.
- Release WebGL은 압축된 `.unityweb` 파일의 실제 크기와 응답 `Content-Encoding`을 함께 확인한다. Brotli 파일은 서버가 `Content-Encoding: br`을 전달해야 브라우저 네이티브 해제 경로를 사용하며, 누락 시 Unity loader의 JavaScript fallback이 동작한다.
- 빠른 시작 판정은 페이지 진입부터 시작 화면 표시, 시작 입력부터 조작 가능 상태까지를 냉 캐시와 동일 버전 재방문으로 나누어 기록한다.
- 빌드 용량을 줄일 때는 Unity Build Report의 실제 packed asset 목록을 기준으로 판단한다. 소스 폴더의 고해상도 모델·텍스처·BGM·콘셉트 자료 크기만으로 빌드 포함을 단정하지 않는다.

## 기능 우선순위

### 1순위: 한 판 완주

- 플레이어 이동과 카메라
- 무기 1종의 사격과 단일 보유 탄약
- 자폭 적의 추적과 폭발
- 적 처치 후 탄약 획득
- 체력, 피해, 사망, 재시작
- WebGL 실행 확인

### 2순위: 고정 콘텐츠 완성

- 클래스 3종의 고정 2무기와 고유 스킬 완성
- DMR을 포함한 일반 무기 4종 완성
- 일반 근거리 적과 원거리 공격 적 추가
- 시간에 따른 연속 난이도 상승
- 점수, 헤드샷, 콤보
- HUD와 결과 화면
- 개인 최고 기록
- 기본 시각·청각 피드백

### 3순위: 필수 후순위

- 닉네임 입력과 검증
- 점수 제출
- 상위 10개 기록 표시
- 현재 점수의 백분위 표시
- 통신 실패 후 재시도

온라인 랭킹은 후순위이지만 최종 제출 대상에서는 제거하지 않는다.

## 제외 범위

- 확정된 DMR 외 추가 무기 또는 네 번째 적
- 두 번째 맵과 스테이지 선택
- 보스, 클리어 조건, 엔딩
- 성장 선택지, 강화 카드, 스킬 트리, 스킬 레벨
- 대시, 클래스별 패시브, 확정된 세 고유 스킬 외 특수 능력
- 환경 파괴와 물리 퍼즐
- 중앙 플랫폼의 실제 이동
- 실시간 멀티플레이와 계정 로그인
- 랭킹 시즌, 친구 순위, 프로필, 업적
- 추가 난이도 모드와 별도 튜토리얼 스테이지

## 제출 가능 판정

아래 조건을 모두 만족해야 제출 가능한 버전으로 판단한다.

- 브라우저에서 게임을 시작할 수 있다.
- 매 판 시작 전에 클래스 하나를 다시 선택한다.
- 조작 안내를 본 뒤 별도 설명 없이 이동과 사격을 할 수 있다.
- 적 3종의 공격 방식과 대응법을 구분할 수 있다.
- 선택한 클래스의 주무기·권총을 전환하고 두 탄약을 회수하며 고유 스킬을 사용할 수 있다. 저격수는 파란색 DMR 탄약을 별도 슬롯에서 소비한다.
- 시간이 지날수록 전투 압박이 계속 증가한다.
- 사망 후 점수, 생존 시간, 개인 최고 기록을 확인할 수 있다.
- 닉네임을 입력해 점수를 제출하고 상위 10개와 백분위를 확인할 수 있다.
- 랭킹 연결 실패가 재시작을 막지 않는다.
- 같은 브라우저에서 개인 최고 기록이 유지된다.
- 결과 화면에서 즉시 다시 시작할 수 있다.

## 범위 축소 원칙

일정이 부족하면 콘텐츠 수를 늘리지 않고 표현 복잡도를 먼저 낮춘다.

1. 장식 오브젝트와 보조 애니메이션 축소
2. 이펙트 변형 수 축소
3. 효과음 변형 수 축소
4. UI 장식 축소

클래스 3종의 고정 로드아웃·고유 스킬, 적 3종, 맵 1개, 한 판의 전체 흐름과 최종 랭킹은 삭제 대상이 아니다.
